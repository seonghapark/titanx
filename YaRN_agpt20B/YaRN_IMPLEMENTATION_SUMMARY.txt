WHAT IS YaRN?
==============

YaRN (Yet Another RoPE Extension) enables context length extension via:

1. Frequency-Aware Interpolation:
   - Low frequencies: Extrapolated (1.0x, unchanged)
   - High frequencies: Interpolated (rope_factor x)
   - Smooth transition between regions

2. NTK-by-Parts Method:
   - Dynamic interpolation ramp between beta_fast and beta_slow
   - Preserves learned low-frequency patterns
   - Compresses high-frequency information

3. Attention Correction:
   - mscale = 0.1 * log(rope_factor) + 1.0
   - Adjusts softmax temperature for scaled dimensions
   - Prevents attention distribution collapse

Result: Stable learning at longer sequences with minimal fine-tuning

Reference: https://arxiv.org/abs/2309.00071

TROUBLESHOOTING
================

Problem: Loss spikes immediately
  → Check original_seq_len matches checkpoint's actual training length (8192)
  → Verify rope_factor appropriate for model dimensions

Problem: CUDA OOM during training
  → Reduce SEQ_LEN or increase TP (tensor parallelism)
  → Enable activation checkpointing (set in config)

Problem: Loss diverges after few steps
  → rope_factor too aggressive; try 1.5 instead of 2.0
  → Jump in seq_len too large; use intermediate length first

Problem: Validation script fails
  → Check config.json has rope_scaling block
  → Verify rope_theta and hidden_size are correct
  → Run with verbose output: python3 -u yarn_validation_agpt20b.py

Problem: Training hangs on init
  → Check CKPT path points to valid DCP checkpoint
  → Verify MODEL_PATH points to valid safetensors
  → Test with TRAINING_STEPS=1 to isolate init issues
